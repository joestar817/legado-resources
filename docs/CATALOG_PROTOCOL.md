# 资源目录协议 v1

本协议用于资源目录、版本比对与安装来源映射。它不替代 NG 现有字体、背景、TTS 或主题的导入和配置模型。

## 源与目录

`main` 保存 `catalog.config.json`、资源文件、`*.resource.json` 和工具。`catalog` 分支只保存生成结果：

```text
catalog.json
fonts/index.json
backgrounds/index.json
tts/index.json
themes/index.json
state.json
```

发布器从获准的 `main` 历史提交提取 Git blob，并生成完整快照。生成索引不回写 `main`。一次更新将所有索引和台账写成一个提交，普通快进推送到 `catalog`；禁止强推覆盖。失败不移动该公开分支。

首次初始化必须明确使用 `--bootstrap`，或手动运行 Actions 时勾选对应选项；已有目录时禁止再次初始化。普通自动任务遇到目录分支不存在也会失败，避免误删目录后从版本 1 重建。PR 检查先读取官方目录台账，再校验候选资源的历史身份约束；尚未初始化目录时需先完成这一初次设置。

NG 应先固定一个 `catalog` 提交，从该提交读取根目录和分类索引，再使用其中的 `sourceCommit` 下载资源。不使用变化中的 `main` 地址代替这个来源提交。

## 总目录

```json
{
  "schemaVersion": 1,
  "sourceCommit": "0000000000000000000000000000000000000000",
  "categories": [
    { "id": "fonts", "name": "字体", "type": "font", "index": "fonts/index.json", "count": 0 },
    { "id": "tts", "name": "TTS", "type": "tts", "index": "tts/index.json", "count": 1 }
  ]
}
```

此处全零提交号仅用于文档示例。正式发布器必须使用获准来源分支的真实 Git 提交。

## 分类索引

每个索引包含 `schemaVersion`、相同的 `sourceCommit`、分类的 `type` 和按稳定 ID 排序的 `resources`。每项资源包含：

| 字段 | 说明 |
|---|---|
| `id` | 稳定身份，全目录唯一；大小写变体也不得重复 |
| `name`、`author`、`license` | 名称、作者、授权声明 |
| `versionCode` | 自动维护的正整数修订号 |
| `versionName` | 可选的作者版本，仅展示 |
| `payload.path`、`format` | 仓库相对路径、载荷格式 |
| `payload.size`、`sha256` | 实际内容字节数及 SHA-256 |
| `payload.engineId` | TTS 从脚本 `@uuid` 提取的原生引擎身份 |
| `requirements` | 可选的 `minAppVersionCode` 与 `capabilities` |
| `description`、`changelog`、`tags` | 可选展示信息 |
| `verification` | 可选的验证日期、状态和说明，不代表生成器执行过服务验证 |

同 ID 的类型及 TTS 引擎身份不得变化。文件名／路径仅定位载荷，不能当作资源身份。索引格式版本、机器修订、作者版本和 App 版本分别有自己的语义。

## 自动版本

发布器读取上次成功发布的 `state.json`，按资源 ID 对比安装内容指纹。指纹包含类型、格式、实际文件摘要及 TTS 引擎 ID；展示信息、下载源路径和兼容要求不计入当前单文件安装指纹。

- 第一次出现：版本 1。
- 安装内容不变：沿用版本；重复任务不额外升版。
- 安装内容改变：版本加一；恢复到历史内容也是一次新修订。
- 只改介绍、作者版本、兼容提示或移动文件：重新生成目录，安装版本保持。
- 删除：公开索引移除，台账保留最后版本、指纹及 `active: false`。
- 同 ID 重新加入：依据历史版本继续，不从 1 重置；同一历史 TTS 引擎 ID 不得换成另一个资源 ID 重新占用。

兼容条件变化仍会更新目录，NG 每次安装或更新都应重新判断兼容性，不能仅比较 `versionCode`。将来如果增加会改变安装结果的参数，必须同步修改指纹协议及测试。

台账至少包含 `schemaVersion`、`sourceCommit` 和 `resources` 映射。每条记录为 `type`、`versionCode`、`fingerprint`、`active`，TTS 另有必需 `engineId`。已有台账损坏、缺失或来源历史分叉时停止发布，不能静默初始化成版本 1。

## 安全与一致性边界

生成器不执行任何资源 JS。拒绝路径越界、绝对路径、反斜杠路径、链接、重复资源／载荷／原生引擎身份和手填机器字段。格式检查限于文件后缀、类型、大小与摘要，不解码字体／图片或完整验证主题 ZIP；实际安装继续由 NG 的对应导入器负责。

普通资源按 Git 中的内容生成摘要，避免 Windows 换行转换导致本地字节与服务器文件不一致。LFS 要求真实对象已经可用且与 Git 指针的 oid／size 一致，生成器拒绝未展开的指针。客户端 LFS 下载入口和真实 GitHub LFS 流量尚需单独验收。

发布任务除了串行运行，还检查候选来源是否落后于已发布来源，并在推送前重读目录分支。并发变化或推送被拒绝时退出，下一次重跑重新计算；不能绕过快进检查。

## 本地安装记录

NG 后续应独立保存来源仓库、资源 ID、已安装版本、载荷摘要、来源提交和实际本地文件／业务对象 ID。安装记录只有在对应模块成功安装后才更新。

自动归类表示加入资源库，不自动切换字体、背景、主题或启用 TTS。下载失败、更新不兼容、远端删除均保留现有安装。用户编辑的内容与个人配置不能直接被云端版本覆盖。

当前仓库仅实现生成与发布协议，尚未修改 NG 的安装器或资源中心 UI。
