# 资源目录协议 v1

本协议用于资源目录、版本比对与安装来源映射。它不替代 NG 现有字体、背景、TTS 或主题的导入和配置模型。

## 源与目录

`main` 将资源文件和 `*.resource.json` 统一放在 `resources/<分类>/`，根目录保留 `catalog.config.json`、文档和工具。`resources/` 必须存在且不能是链接；分类 ID 和资源 ID 不因增加这一层目录改变。`catalog` 分支同样将分类索引收在 `resources/` 下，只保存生成结果：

```text
catalog.json
resources/fonts/index.json
resources/backgrounds/index.json
resources/tts/index.json
resources/themes/index.json
state.json
previews/<图片SHA256>.png
```

发布器从获准的 `main` 历史提交提取 Git blob，并生成完整快照。生成索引不回写 `main`。一次更新将所有索引和台账写成一个提交，普通快进推送到 `catalog`；禁止强推覆盖。失败不移动该公开分支。

首次初始化必须明确使用 `--bootstrap`，或手动运行 Actions 时勾选对应选项；已有目录时禁止再次初始化。普通自动任务遇到目录分支不存在也会失败，避免误删目录后从版本 1 重建。PR 检查先读取官方目录台账，再校验候选资源的历史身份约束；尚未初始化目录时需先完成这一初次设置。

NG 应先固定一个 `catalog` 提交，从该提交读取根目录、分类索引和预览图，再使用其中的 `sourceCommit` 下载资源。不使用变化中的 `main` 地址代替这个来源提交。预览图不在源提交中；客户端必须保存每项预览对应的目录提交，不能用新的目录提交读取旧详情/旧安装记录的图片。

## 总目录

```json
{
  "schemaVersion": 1,
  "sourceCommit": "0000000000000000000000000000000000000000",
  "categories": [
    { "id": "fonts", "name": "字体", "type": "font", "index": "resources/fonts/index.json", "count": 0 },
    { "id": "tts", "name": "TTS", "type": "tts", "index": "resources/tts/index.json", "count": 1 }
  ]
}
```

此处全零提交号仅用于文档示例。正式发布器必须使用获准来源分支的真实 Git 提交。

## 分类索引

每个索引包含 `schemaVersion`、相同的 `sourceCommit`、分类的 `type` 和按稳定 ID 排序的 `resources`。每项资源包含：

| 字段 | 说明 |
|---|---|
| `id` | 稳定身份，全目录唯一；大小写变体也不得重复 |
| `name`、`author` | 名称、作者 |
| `license` | 可选的授权声明；缺省时不推断 |
| `publishedAt`、`updatedAt` | 自动维护的 UTC ISO8601 时间，首次收录与最近一次安装内容变更 |
| `versionCode` | 自动维护的正整数修订号 |
| `versionName` | 可选的作者版本，仅展示 |
| `payload.path`、`format` | 带 `resources/<分类>/` 前缀的仓库相对路径、载荷格式 |
| `payload.size`、`sha256` | 实际内容字节数及 SHA-256 |
| `payload.engineId` | TTS 从脚本 `@uuid` 提取的原生引擎身份 |
| `requirements` | 可选的 `minAppVersionCode` 与 `capabilities` |
| `description`、`changelog`、`tags` | 可选展示信息 |
| `preview` | 字体的自动缩略图和详情样张，仅生成器输出，投稿不填写 |

同 ID 的类型及 TTS 引擎身份不得变化。文件名／路径仅定位载荷，不能当作资源身份。索引格式版本、机器修订、作者版本和 App 版本分别有自己的语义。

资源元数据不维护校验日期、测试状态或验证过程；这些记录放在投稿说明或本地诊断中，不作为资源内容维护。

## 字体预览

正式 `generate` 和发布流程在精确的源文件快照上自动渲染字体。`validate`、PR 投稿校验和纯 `buildCatalog` 不启动渲染器，不执行投稿代码。字体源目录仍只有字体与 `*.resource.json`，作者不能手写 `preview`。

字体索引项可包含：

```json
"preview": {
  "thumbnail": { "path": "previews/<sha256>.png", "size": 1234, "sha256": "<sha256>", "width": 256, "height": 256 },
  "detail": { "path": "previews/<sha256>.png", "size": 12345, "sha256": "<sha256>", "width": 960, "height": 420 }
}
```

这里的占位摘要仅用于说明。实际图片必须是相应尺寸的非交错8位RGBA PNG，文件不超过1MiB，路径必须与真实SHA256一致。单色透明字形供客户端按主题着色；方形图用于列表/网格，宽图用于详情，不能将宽图裁成方图。图片与索引在同一暂存目录写入并原子发布；拒绝孤立图片、不匹配的引用、路径越界、链接和非生成文件。

缩略图从字体自身字符映射及真实轮廓选择可见样字，全部使用源字体。详情固定为三行：`中国智造，慧及全球`、`Innovation in China` 和 `0123456789.:;'"(!?)+-*/=`，优先使用源字体已有字形；缺字使用 `tools/fonts/preview-fallback.ttf` 的固定 Noto Sans SC 子集。因此详情是混排样张，不代表源字体覆盖所有展示字符。补字文件仅在需要时读取，路径相对受信渲染器固定，校验 SFNT、SHA256 和全部样字覆盖；禁止从系统字体或外部路径补字。相邻同字体字符按连续字串排版，使用实际字距与共同基线，空格使用有效前进宽度。源字体无可见字形仍直接拒绝，不能由补字文件代替无效资源。

固定渲染规则版本为 `font-sample-v2`，保持256×256缩略图和960×420详情，详情使用两档字号、居中并限界缩放。输入字体最多64MiB，每次调用有30秒时限；同次生成的相同字体SHA只渲染一次。渲染子进程不继承发布token、Git认证配置或外部Python导入路径。依赖与Python版本由发布工作流固定，Windows本地若没有RAQM应使用具备同环境的Python，而不是降级生成另一种样图。补字依赖来源和重建方法见 `tools/fonts/README.md`。

预览、样例文本、渲染规则不参与安装指纹或时间算法。样图改变通过图片SHA更新缓存；字体文件未改变时，安装版本和发布时间/更新时间保持。历史预览通过历史目录提交继续可读，不需要把旧图累积到最新目录。

## 自动时间

时间由发布器从受信 `sourceCommit` 的 Git committer time 生成并规范成 `YYYY-MM-DDTHH:mm:ss.sssZ`，禁止在资源说明中手填。首次收录时 `publishedAt = updatedAt = sourceTime`；指纹改变时仅更新 `updatedAt`；说明、路径、重复发布、删除或同内容重新加入都保持原日期。日期不参与安装指纹或版本比较。内容升版的源时间如果早于已记录更新时间，发布会失败，不回拨或改写时间。

旧目录缺日期不会由运行时自动修复。维护者显式调用 `--initialize-dates`（或手动工作流的 `initialize_dates`）后，发布器读取完整、非浅、单亲 catalog 历史，按每次台账的受信来源提交时间恢复首次出现/指纹变化时间；保持原版本、指纹和删除记录。缺失历史、身份变化、版本跳跃、时间倒退或既有日期与历史不一致时失败，不猜时间或重置版本。初始化后重复运行保持同一结果。

投稿 `validate` 仍可读取无日期旧台账，且不会补造时间。独立 `generate` 必须显式提供来自源提交的 `--source-time` UTC 时间；内部 `buildCatalog` 省略 `sourceTime` 仅供校验，不用于发布。

## 自动版本

发布器读取上次成功发布的 `state.json`，按资源 ID 对比安装内容指纹。指纹包含类型、格式、实际文件摘要及 TTS 引擎 ID；展示信息、下载源路径和兼容要求不计入当前单文件安装指纹。

- 第一次出现：版本 1。
- 安装内容不变：沿用版本；重复任务不额外升版。
- 安装内容改变：版本加一；恢复到历史内容也是一次新修订。
- 只改介绍、作者版本、兼容提示或移动文件：重新生成目录，安装版本保持。
- 删除：公开索引移除，台账保留最后版本、指纹及 `active: false`。
- 同 ID 重新加入：依据历史版本继续，不从 1 重置；同一历史 TTS 引擎 ID 不得换成另一个资源 ID 重新占用。

兼容条件变化仍会更新目录，NG 每次安装或更新都应重新判断兼容性，不能仅比较 `versionCode`。将来如果增加会改变安装结果的参数，必须同步修改指纹协议及测试。

台账至少包含 `schemaVersion`、`sourceCommit` 和 `resources` 映射。每条记录为 `type`、`versionCode`、`fingerprint`、`active`、`publishedAt`、`updatedAt`，TTS 另有必需 `engineId`。已有台账损坏、缺失或来源历史分叉时停止发布，不能静默初始化成版本 1。

## 安全与一致性边界

生成器不执行任何资源 JS。拒绝路径越界、绝对路径、反斜杠路径、链接、重复资源／载荷／原生引擎身份和手填机器字段。格式检查限于文件后缀、类型、大小与摘要，不解码字体／图片或完整验证主题 ZIP；实际安装继续由 NG 的对应导入器负责。

普通资源按 Git 中的内容生成摘要，避免 Windows 换行转换导致本地字节与服务器文件不一致。LFS 要求真实对象已经可用且与 Git 指针的 oid／size 一致，生成器拒绝未展开的指针。客户端 LFS 下载入口和真实 GitHub LFS 流量尚需单独验收。

发布任务除了串行运行，还检查候选来源是否落后于已发布来源，并在推送前重读目录分支。并发变化或推送被拒绝时退出，下一次重跑重新计算；不能绕过快进检查。

## 本地安装记录

NG 独立保存来源仓库、资源 ID、已安装版本、载荷摘要、来源提交和实际本地文件／业务对象 ID。安装记录只有在对应模块成功安装后才更新。

自动归类表示加入资源库，不自动切换字体、背景、主题或启用 TTS。下载失败、更新不兼容、远端删除均保留现有安装。用户编辑的内容与个人配置不能直接被云端版本覆盖。

NG 资源中心已实现目录与单文件安装消费；日期在详情页按设备时区显示，缺失或非法日期显示“—”，不会以当前时间兜底。
